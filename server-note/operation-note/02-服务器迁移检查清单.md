# 服务器迁移检查清单

---

**最后更新时间：2026年8月6日**

---

> **适用场景**：旧服务器优惠到期，换新服务器薅羊毛
> **预计耗时**：2~4 小时（视数据量而定）
> **迁移原则**：先基础环境 → 再数据 → 再应用 → 最后验证
> **⚠️ 重要**：旧服务器先不要停，新的完全跑通再切流量、再销毁旧的

---

## 一、迁移前准备

- [ ] 新服务器已购买并能 SSH 登录
- [ ] 旧服务器数据已备份（宝塔一键备份 / 手动备份）
- [ ] 域名解析准备好（迁移完再切）
- [ ] CDN 服务暂停（如果有）

> 💡 有 CDN 的先停 CDN，否则可能缓存旧数据影响验证

---

**服务器安全组 + 宝塔安全组，两边都要开！**

## 三、数据库迁移

### ✅ MySQL 迁移

```bash
# 1. 宝塔安装 MySQL（选对应版本）
# 2. 修改 root 密码
# 3. 本地连接验证
mysql -u root -p

# 4. 赋予远程连接权限（DBeaver 等工具需要）
GRANT ALL PRIVILEGES ON `数据库名`.* TO '用户名'@'远程IP' IDENTIFIED BY '密码' WITH GRANT OPTION;
FLUSH PRIVILEGES;

# 5. 宝塔备份功能迁移数据（最简单）
# 旧服务器备份 → 下载备份文件 → 新服务器上传恢复
```

> 💡 远程连接前一定要先授权；宝塔备份恢复最省心，不建议手动导 SQL

---

### ✅ Redis 迁移

```bash
# ===== 旧服务器上 =====
# 1. 宝塔安装 Redis
# 2. 修改配置：
#    - requirepass 设置密码
#    - 注释 bind 127.0.0.1 或改为 bind 0.0.0.0
#    - protected-mode 改为 no
# 3. 本地 + 远程工具连接验证（redis-cli + RedisDesktopManagement）

# 4. 创建数据快照（BGSAVE 异步，不阻塞）
redis-cli
# 输入密码认证后执行
BGSAVE

# 5. 找到 dump.rdb（redis.conf 中 dir 选项指定位置）
# 6. 复制到新服务器
scp /path/to/redis/dump.rdb user@newserver:/path/to/redis/

# ===== 新服务器上 =====
# 7. 停止 Redis 服务
# 8. dump.rdb 放到 Redis 工作目录
# 9. 启动 Redis
redis-server --port 6379 --bind 0.0.0.0 --dir /path/to/redis/ --dbfilename dump.rdb
```

> 💡 避坑：
> - `BGSAVE` 后台保存不阻塞，`SAVE` 同步保存会阻塞，生产用 BGSAVE
> - 宝塔 Redis 默认关闭日志，需要的话面板开启
> - 一定要先停新 Redis 再覆盖 dump.rdb

---

### ✅ MongoDB 迁移

```bash
# 1. 宝塔安装 MongoDB
# 2. 修改 Node 应用 .env 文件中 MongoDB 连接地址
# 3. pm2 重启并更新环境变量
pm2 restart <应用名称> --update-env
```

> ⚠️ MongoDB 迁移记录较少，数据量大建议用 mongodump/mongorestore

## 四、后端服务迁移

### ✅ Java / 若依后台

```bash
# 1. 宝塔安装 JDK 1.8 + Tomcat 9
# 2. 上传服务包至 /home/ruoyi
# 3. 宝塔界面配置服务并启动

# 基础启动命令
/usr/local/btjdk/jdk8/bin/java -jar -Xmx1024M -Xms256M /home/ruoyi/ruoyi-admin.jar --server.port=9897

# 超神服务（内存不够时减配启动）
/usr/bin/java \
-Xms128M -Xmx512M \
-XX:MetaspaceSize=64M -XX:MaxMetaspaceSize=128M \
-XX:MaxDirectMemorySize=128M \
-XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
-Dlogging.pattern.console="%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n" \
-Dlogging.file.max-size=100MB -Dlogging.file.max-history=7 \
-jar /home/ruoyi-chaoshen/ruoyi-admin.jar \
--server.port=9797 \
--spring.boot.admin.enabled=false \
--management.endpoints.web.exposure.include= \
--spring.cache.type=none \
--ruoyi.log.desensitize=false
```

> 💡 避坑：
> - 若依默认 9897，超神服务 9797，别搞混
> - 内存不够就用减配版，堆内存、元空间都调小
> - 超神服务关闭了 Spring Boot Admin、监控端点、缓存，进一步省内存

### ✅ Node 服务

```bash
# 1. 旧服务器 /usr/node 目录拷贝到新服务器同目录
#    ⚠️ 不要拷贝 node_modules 目录！
# 2. 安装 Node 和 PM2
#    node@14.16.0 / pm2@4.5.5

# 3. 安装依赖并启动
cd /usr/node/NPPBE
npm install
cd bin
pm2 start www --name="NPPBE"

# 4. 确认 .env 环境变量文件存在且配置正确
```

> 💡 避坑：
> - 一定不要拷贝 `node_modules`，体积大且可能有平台兼容性问题
> - `.env` 文件很重要，别漏了
> - 迁移后检查 MongoDB 等外部连接地址

### ✅ Jenkins（Tomcat 部署）

```bash
# ===== 旧服务器备份 =====
# 1. Tomcat 安装包（/usr/soft/sort）
# 2. Jenkins 数据目录（最重要！）
#    /root/.jenkins 下的 jobs / plugins / secrets / users / config.xml
# 3. 整个 Tomcat 目录（/usr/soft/install/apache-tomcat-9.0.7）

# ===== 新服务器部署 =====
# 4. 上传 Tomcat 安装包到 /usr/soft/sort
# 5. 解压
tar -zxvf /usr/soft/sort/apache-tomcat-9.0.7.tar.gz -C /usr/soft/install/

# 6. 配置环境变量
vim /etc/profile
# 最后添加：
# export CATALINA_HOME=/usr/soft/install/apache-tomcat-9.0.7
# export CATALINA_BASE=/usr/soft/install/apache-tomcat-9.0.7

# 7. 立即生效
source /etc/profile

# 8. 用备份的 Tomcat 目录覆盖新安装的
#    ⚠️ 先删除新 Tomcat 的 webapps/jenkins 文件夹！

# 9. 启动 Tomcat
cd /usr/soft/install/apache-tomcat-9.0.7/bin
./startup.sh
# 访问 IP:端口 看到 Tomcat 主页就算成功

# 10. 先走 Jenkins 新手流程，然后关闭 Tomcat
# 11. 用备份的 /root/.jenkins 覆盖新服务器同目录
# 12. 重新启动 Tomcat
```

> 💡 避坑：
> - `secrets` 文件夹覆盖后凭证能否直接用不确定，不行的话需要重新添加，每个流程都要重新用新凭证
> - 启动前一定要删干净新 Tomcat 自带的 jenkins 文件夹，否则冲突
> - 环境变量改的是 `/etc/profile`（没有后缀）
> - vim 操作：按 `i` 编辑，`Esc` 退出编辑，`:wq` 保存退出

### ✅ Halo 博客迁移

#### 前置准备

```bash
# 新服务器安装 JDK 11
sudo apt update && sudo apt install openjdk-11-jdk   # Ubuntu/Debian
sudo yum install java-11-openjdk                    # CentOS
```

#### 导出旧数据

```bash
# 1. 旧服务器先不要停
# 2. Halo 后台 → 工具 → 导出数据（导出 data.json）
# 3. xftp 导出 /home/halo/.halo 目录所有文件
#    ⚠️ upload 文件夹有中文名图片，xftp 属性改为 UTF-8，否则导出报错
# 4. 停 CDN（如果有）
# 5. 域名解析指向新服务器 IP
# 6. 新服务器开放 8090 端口
```

#### 新服务器安装

```bash
# 1. 创建 halo 用户
useradd -m halo-fx67ll
usermod -aG sudo halo-fx67ll
passwd halo-fx67ll
su - halo-fx67ll

# 2. 下载 Halo 运行包
mkdir ~/app && cd ~/app
RELEASE_URL=$(curl -s https://api.github.com/repos/halo-dev/halo/releases/tags/v1.5.2 | grep "browser_download_url.*halo-1.5.2.jar" | cut -d '"' -f 4)
wget "$RELEASE_URL" -O halo.jar

# 3. 创建工作目录 + 配置文件
mkdir ~/.halo && cd ~/.halo
# 直接用老的配置文件，丢失了就手动重建：
cat > application.yaml <<'EOF'
server:
  port: 8090
  compression:
    enabled: false

spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:file:~/.halo/db/halo
    username: ******
    password: ******

  h2:
    console:
      enabled: false
      settings:
        web-allow-others: false
EOF

# 4. 测试运行
cd ~/app && java -jar halo.jar
# 看到 Halo started successfully! 就算成功
# Ctrl+C 停止测试
```

#### 配置为系统服务

```bash
# 退回 root
exit

cat > /etc/systemd/system/halo.service <<'EOF'
[Unit]
Description=Halo Service
Documentation=https://docs.halo.run
After=network.target

[Service]
Type=simple
User=halo-fx67ll
Group=halo-fx67ll
WorkingDirectory=/home/halo-fx67ll/app
ExecStart=/usr/bin/java -jar /home/halo-fx67ll/app/halo.jar
Restart=always
StandardOutput=journal+console
StandardError=journal+console

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl start halo
systemctl enable halo
systemctl status halo
```

#### 导入数据

```bash
# 1. 先配 Nginx（建议先不配置 HTTPS，确保 HTTP 能访问再说）
# 2. 启动 Halo，引导界面选择导入老数据，用 data.json
# 3. 停止 Halo，把备份的 .halo 目录覆盖到新服务器同目录
# 4. 重新启动 Halo
```

> 💡 避坑：
> - 建议先配 HTTP 确保能访问，再配 HTTPS
> - xftp 传中文文件一定要改 UTF-8 编码，否则文件名乱码
> - 导入数据和覆盖文件时，最好两边都停掉 Halo
> - H2 控制台和远程访问平时都关掉

## 六、Nginx 配置 + SSL

### 宝塔面板域名绑定 + SSL

```bash
# 1. 先关闭面板本身的 SSL 开关
#    可视化界面关不一定成功，用 bt 命令关闭

# 2. 绑定域名（可选，不绑定也能用 IP+端口）
#    绑定后访问方式：域名+端口号

# 3. 80 端口代理宝塔 HTTP 地址
# 4. 443 端口配置 HTTPS
```

### Nginx 配置示例

```nginx
server {
    listen  80;
    server_name ez13.top;
    location / {
        proxy_pass https://baota.fx67ll.com:10234;
    }
}

server {
    listen 443 ssl;
    server_name ez13.top;

    ssl_certificate     /etc/ssl/ez13.top/ez13.top.crt;
    ssl_certificate_key /etc/ssl/ez13.top/ez13.top.key;
    ssl_protocols       TLSv1.1 TLSv1.2 TLSv1.3;
    ssl_ciphers         ECDHE-RSA-AES128-GCM-SHA256:HIGH:!aNULL:!MD5:!RC4:!DHE;
    ssl_prefer_server_ciphers on;
    ssl_session_cache   shared:SSL:1m;
    ssl_session_timeout 10m;

    location / {
        proxy_pass https://baota.fx67ll.com:10234;
    }
}
```

### SSL 证书更新（每年一次）

```bash
# 1. 证书下发前选择 DNS 自动验证
#    ⚠️ 记得删除之前的验证记录！

# 2. 重新签发后，检查证书域名和 nginx.conf 中指向的是否一致！

# 3. 证书统一存放在 /etc/ssl 目录下

# 4. 更换后需要等缓存清除，不要心急！
#    浏览器可能缓存旧证书，用无痕模式或清缓存测试
```

> 💡 避坑：
> - DNS 验证前删旧验证记录，否则可能冲突
> - 证书域名和 server_name 必须一致
> - 换完证书别急，等缓存清了再验证

## 九、常见问题

### 访问 HTML 报 403 权限不足

```bash
# Nginx 用户对静态文件目录没有读取权限
chmod -R 755 /usr/share/nginx/html-8070   # 目录权限
chmod 644 /usr/share/nginx/html-8070/index.html  # 文件权限
```

### Nginx 配置不生效

```bash
nginx -t          # 检查语法
nginx -s reload   # 重载配置
```
